## 2. 目标与训练流程中的位置

RLVR 的每个 prompt 通常生成一组回答，再用可验证奖励计算组内相对优势。普通独立随机采样可能得到多条近似推理路径，造成探索冗余；相同奖励还可能使组内优势失去区分度。

LATR 通过生成过程中的分叉、前瞻和剪枝，提高同一 prompt 下的轨迹差异。它主要改变 rollout 策略，原则上可以复用 GRPO、DAPO 的奖励、优势与策略更新模块。

```text
prompt
  -> LATR/普通采样组成的 rollout group
  -> 完整回答的可验证奖励
  -> 按 prompt 分组计算优势
  -> 使用模型概率计算策略损失
  -> 更新模型
```

几个需要始终保留的认识：

- 轨迹差异是探索指标，不等价于答案正确性，也不保证准确反映语义差异。
- 默认算法不用 reward model 或最终答案奖励决定树内保留哪个分支。
- 没有 MCTS 式访问计数、UCB 选择或奖励回传。
- lookahead 的延伸是实际生成的轨迹，保留下来的 token 会进入最终回答；不是完成一段模拟后丢弃、回退并重新解码。
- 算法不回溯；剪枝后保留其他路径继续向前生成。

## 3. 符号

| 符号 | 含义 |
| --- | --- |
| `p` | prompt |
| `π` | 当前 rollout 使用的策略模型 |
| `k` | 每个 prompt 的目标回答数，同时约束树宽 |
| `n` | 最大回答 token 数，不包含 prompt |
| `S_l` | 第 `l` 步的活动路径集合 |
| `s` | 某条部分回答 |
| `P_s(c)` | 给定 `p + s` 后，下一个 token 为 `c` 的概率 |
| `c*` | 下一个 token 的最高概率候选 |
| `τ_abs` | 创建分支的绝对概率下限 |
| `τ_rel` | 次候选与最高概率候选之间的概率差上限 |
| `r` | 前瞻比较窗口 |
| `τ_ed` | 归一化编辑距离下限 |
| `η` | 每组回答中分配给 LATR 的比例 |

## 4. 分叉

从每个 prompt 的单条根路径开始。给定路径 `s`：

1. 用策略模型得到完整词表上的下一 token 概率 `P_s`。
2. 原路径接上 `c* = argmax_c P_s(c)`。
3. 对其他候选 `c != c*`，同时满足以下条件时允许创建子路径：

   ```text
   P_s(c) > τ_abs
   P_s(c*) - P_s(c) < τ_rel
   ```

4. 新路径复制公共前缀，接上不同候选，记录父路径与出生步数。
5. 所有活动路径的数量受每个 prompt 的预算 `k` 限制。

这种规则用概率分布上的竞争候选识别高不确定性位置，不需要显式计算 entropy。阈值也限制分支偏离模型原分布的程度。

论文表示，当预算不足时按候选概率降序优先保留。旧代码的容量分配规则有更具体的顺序，详见配套代码文档，不能直接视为全局按概率排序。

## 5. 前瞻与剪枝

子路径继续向前生成，在出生后到达指定窗口时，与其父路径的对应延伸片段比较。

论文公式 (7) 使用 token ID 序列上的 Levenshtein 距离，并除以比较长度：

```text
d(child, parent; r)
    = Levenshtein(child 的比较片段, parent 的比较片段) / r

若 d < τ_ed：删除 child 及其全部后代
否则：通过该次检查
```

实际含义：

- 比较对象是父子路径，不是任意两条存活路径的全量两两比较。
- 在前瞻期间，分支本身还可以继续分叉；因此存在嵌套父子关系。
- 删除整棵后代子树可以防止被判为冗余的路径通过后代继续占用名额。
- 释放名额后，其他存活路径可在后续 token 位置产生新分支。

附录 B.3 的实验同时使用 `r = [20, 30, 50]`。同一分支在相应年龄分别被检查，任一次不满足距离条件即被剪掉；不是先通过 20-token 检查就永久免检。

论文算法的前向计算量上界表述为 `O(nk)`。这不代表墙钟时间一定快于 vLLM 的普通采样；动态增删行、距离比较、缓存操作会带来额外开销。

## 6. 退出树形生成与补齐

论文第 3.3 节提出：达到目标树宽后，将存活的部分回答转为标准随机采样，完成剩余生成。

必须区分：

- Algorithm 1 是主体机制的简化表述。
- 实际工程实现还有最长前瞻等待、近似饱和阈值、硬性长度上限、跨 rank 同步等规则。
- 最终不足 `k` 条时需要补齐；复制部分路径并继续随机采样，并不保证补齐结果互不相同。
- EOS、最大长度等终止边界会影响哪些前瞻检查真正发生。

因此，不应宣称最终每条回答都已经通过所有距离检查，或任意两条最终回答一定达到某个差异阈值。

## 7. 与普通采样混合

论文公式 (9)、(10)：

```text
k_LATR = round(η * k)
k_std  = k - k_LATR
η_i    = η_0 * γ^i
```

每个 prompt 的一部分回答使用 LATR，剩余回答用普通随机采样；训练推进时减少 LATR 比例，逐渐接近测试时的采样方式。

需要区分两种“混合”：

| 名称 | 控制内容 |
| --- | --- |
| 采样策略混合 | 同一组中 LATR 回答与普通采样回答的数量 |
| HF/vLLM 混合引擎 | 先由 HF 做树形解码，再由 vLLM 完成普通续写 |

混合引擎是旧实现的工程方案，不是算法定义要求必须存在的两个后端。

## 8. 与 GRPO、DAPO 的关系

GRPO 使用组内奖励均值和标准差计算相对优势，并用当前策略与旧策略的 token 概率比进行 clipped policy update；论文还描述了 reference KL 项。

对组内第 `i` 条回答、位置 `t`，论文公式 (2)、(3) 可写为：

```text
A_i = (R_i - mean(R_1,...,R_k)) / std(R_1,...,R_k)
r_i,t(θ) = π_θ(s_i,t | p,s_i,<t) / π_old(s_i,t | p,s_i,<t)

L_i,t = min(r_i,t * A_i,
            clip(r_i,t, 1-ε, 1+ε) * A_i)

J_GRPO = E[mean_i(mean_t(L_i,t - β * KL_i,t))]
```

同一回答内各 token 共享该回答的组相对优势。实现中需处理零标准差和数值稳定性，不能将论文简式直接用于除零计算。

DAPO 在此基础上涉及组过滤、非对称 clipping、token 级 loss 聚合等。LATR 可以和这些更新方式组合。

论文公式 (4) 用 `clip(r, 1-ε_low, 1+ε_high)`，并将各回答的有效 token 损失求和后除以整组有效 token 总数。与先对各回答内部平均、再对回答平均相比，长回答的权重不同。迁移时要显式设置 loss aggregation，而不是依赖目标版本默认值。

需要将下面几个概念分开：

1. **树内轨迹剪枝**：在回答生成完成之前发生，依据轨迹差异。
2. **DAPO 组过滤**：在奖励可用后发生，去掉奖励无区分度的组，并继续收集训练数据。
3. **RDS/多样性下采样**：先多生成完整回答，再做事后挑选，是论文中的对照策略。

“更新公式可以复用”不代表 LATR 输出仍是独立的原策略随机样本。强制分叉和剪枝会改变采样分布；策略概率、采样概率、rollout correction 的语义必须在适配时单独审查。

## 11. 后续工作必须保留的算法不变量

- 按明确的 prompt/group ID 管理树，不能仅凭 token 内容相同推断为同一组。
- 每个 prompt 的组预算独立，不能把整个 batch 的预算混在一起。
- 分支有稳定身份、父子关系、出生步数和明确的窗口计时定义。
- 剪枝删除后代，且所有与路径关联的状态必须一起更新。
- 概率阈值基于哪种概率要明确：旧核心实现使用未经过 temperature/top-k/top-p 变换的 softmax 概率。
- 提前退出、EOS、复制补齐、标准采样混入必须有可观测的统计。
- 最终奖励仍依据完整回答计算；距离过滤不能替代正确性判断。
